# RequestBuilderABC[RequestT]

## Назначение

`RequestBuilderABC` — контракт для детерминированного построения транспортных запросов к конкретному источнику данных.  
Он **не выполняет сетевые вызовы** и **не реализует ретраи**. Его задача — собрать корректный `RequestT`, который затем передаётся в `SourceClientABC`.

`RequestT` может представлять собой:
- HTTP‑запрос (объект клиента),
- SQL‑запрос/строку + параметры,
- RPC‑вызов,
- любой другой тип запроса, который понимает соответствующий `SourceClientABC`.

## Общее представление интерфейса

```python
from typing import Generic, TypeVar, Optional

RequestT = TypeVar("RequestT")

class RequestBuilderABC(Generic[RequestT]):
    def build_initial(self) -> RequestT:
        """Сформировать первый запрос в последовательности."""
        raise NotImplementedError

    def build_for_page(self, cursor: Optional[str]) -> RequestT:
        """Сформировать запрос для указанной позиции/страницы."""
        raise NotImplementedError
```

## Ответственность

- Инкапсуляция всех правил формирования запросов к конкретному источнику:
  - базовый URL/endpoint,
  - обязательные заголовки,
  - query‑параметры,
  - тело запроса,
  - настройки аутентификации, если они реализуются на уровне запроса.
- Конструирование:
  - **стартового запроса** (`build_initial`),
  - **последующих запросов** на основе курсора/offset/номера страницы (`build_for_page`).

Логика построения запросов должна быть сосредоточена в `RequestBuilderABC`, а не размазана по клиенту, пагинатору или другим слоям.

## Методы

### `build_initial(self) -> RequestT`

Назначение: сформировать первый запрос в последовательности.

Характеристики:
- Не принимает аргументов.
- Использует:
  - конфигурацию (профиль, ключи, базовый URL),
  - внешние зависимости (например, время запуска),
  - внутреннее состояние, зафиксированное при инициализации.
- Типичный сценарий:
  - «первая страница» (page=1),
  - начальный `cursor = None`,
  - стартовый диапазон дат и т.п.

Ошибки:
- При невалидной конфигурации (нет обязательного поля, некорректный формат) **может и должен** выбрасывать исключение.

### `build_for_page(self, cursor: Optional[str]) -> RequestT`

Назначение: сформировать запрос для конкретной позиции в потоке данных.

Параметры:
- `cursor: Optional[str]`:
  - `None` — первая страница или режим «без курсора»;
  - строка, ранее извлечённая через `ResponseParserABC.extract_cursor`.

Требования:
- Builder **не модифицирует** семантически значение курсора «за спиной» вызывающего кода.
- Если нужна сложная структура курсора, она кодируется в строку (например, JSON/base64), формат согласуется с `ResponseParserABC`/`PaginatorABC`.

Ошибки:
- При невалидном курсоре или нарушении протокола может выбрасывать предсказуемое исключение конфигурационного/протокольного уровня.

## Инварианты

- При одинаковом внутреннем состоянии и одном и том же значении `cursor` результат должен быть **идентичным** (детерминированность).
- Любая случайность (idempotency‑key, trace‑id и пр.) выносится во внешние зависимости, чтобы при тестировании можно было переопределить генераторы.
- Возвращаемый `RequestT` обязан быть валиден для связанного `SourceClientABC`.

## Взаимодействие с другими компонентами

- **`SourceClientABC`**:
  - ожидает, что любой `RequestT`, построенный `RequestBuilderABC`, готов к отправке без доработки;
  - дополнительные требования клиента (обязательные заголовки и пр.) учитываются в конкретной реализации builder’а.

- **`PaginatorABC`**:
  - вызывает `build_initial` для стартового запроса;
  - далее использует `build_for_page`, передавая курсор, извлечённый парсером (`ResponseParserABC.extract_cursor`).

## Типизация

- `RequestT` инвариантен.
- Если реализация объявлена как `RequestBuilderABC[HttpRequest]`, **все** публичные методы должны возвращать `HttpRequest`.
- Нельзя:
  - «расширять» до родительского типа в реализации,
  - «сужать» до подтипа в сигнатуре интерфейса.

## Типичные реализации

1. **Builder на основе конфигурационного профиля**
   - В конструктор передаётся `ConfigT` с:
     - базовым URL,
     - ключами доступа,
     - фильтрами по датам/статусу.
   - `build_initial` подставляет стартовые значения.
   - `build_for_page` переиспользует базовые параметры, меняя только курсор/offset/page.

2. **Builder, зависящий от времени запуска**
   - Время запуска передаётся отдельно (в конструктор или через метод инициализации).
   - `build_initial` использует его при формировании диапазона `from/to`.
   - Это время не должно «плавать» между вызовами, чтобы сохранить детерминированность.

## Ошибки использования

- Возврат «пустого» или заведомо невалидного запроса с надеждой, что клиент «догадается, что делать», нарушает контракт.
- Размазывание логики построения запросов по нескольким слоям приводит к неконтролируемым побочным эффектам и усложняет сопровождение.
