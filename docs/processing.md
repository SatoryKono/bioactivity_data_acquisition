# Processing chain (ETL core)

## Expected inputs

* **primary_records** – последовательность словарей ``Mapping[str, object]``.
* **secondary_records** (опционально) – такая же последовательность, используемая merge-стратегией.
* **side inputs** – словари от провайдеров `SideInputProviderABC` (например, справочники), объединяются по имени.

## Pipeline steps

1. **Normalisation** (`NormalizationTransformer`):
   - приводит ключи к нижнему регистру, обрезает пробелы;
   - чистит строковые значения и заменяет пустые строки на ``None``;
   - поддерживает переименование столбцов.
2. **Cleanup** (`CleanupTransformer`):
   - отбрасывает записи без обязательных полей;
   - удаляет указанные поля со значением ``None``;
   - по умолчанию исключает полностью пустые записи.
3. **Side inputs** (`StaticSideInputProvider` и другие):
   - собирают вспомогательные данные (например, справочник стран);
   - передаются в `LookupEnricherABC` перед обогащением.
4. **Lookup-enrichment** (`MappingLookupEnricher`):
   - ищет значение по ключу из ``source_field`` в указанном словаре ``lookup_name``;
   - либо мержит вложенный словарь, либо пишет значение в целевое поле.
5. **Business key** (`SHA256BusinessKeyDeriver`):
   - строит детерминированный SHA-256 хеш (64 символа) из выбранных полей;
   - пишет его в колонку ``business_key`` (по умолчанию).
6. **Hash columns** (`ColumnHashingTransformer`):
   - добавляет SHA-256 хеши по выбранным колонкам с суффиксом ``_hash``.
7. **Merge strategy** (`PreferPrimaryMergeStrategy`):
   - объединяет primary/secondary по бизнес-ключу, приоритет у primary;
   - добавляет все неиспользованные записи secondary в конец.
8. **Deduplication** (`BusinessKeyDeduplicator`):
   - сохраняет первое вхождение каждой пары бизнес-ключей, сохраняя порядок.

## Outputs

* Последовательность словарей, прошедшая все выбранные стадии.
* Каждый словарь детерминированно обогащён, снабжен бизнес-ключом и хэш-колонками (если настроены).

## Guarantees

* Хеши формируются через SHA-256 и всегда имеют длину 64 символа.
* Порядок сохранения записей после дедупликации предсказуем: оставляется первое вхождение.
* Все шаги работают на неизменяемых копиях входных словарей, не модифицируя оригинальные данные.
