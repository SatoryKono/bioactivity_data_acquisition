# Processing Chain: expected inputs and outputs

Документ описывает минимальный контракт для конвейера `ProcessingChain` из `src/bioetl/core/pipeline/processing/chain.py`.

## Входные данные
- Последовательность словарей с произвольными ключами (`Mapping[str, object]`).
- Значения полей могут быть строками, числами или `None`.
- Для обогащения требуется наличие поля, соответствующего `record_key` у `SimpleLookupEnricher`.

## Этапы и их артефакты
1. **NormalizationTransformer**
   - Приводит ключи к нижнему регистру (по умолчанию) и применяет `field_map`.
   - Убирает пробелы по краям строковых значений.
   - **Выход:** такие же словари, но с нормализованными ключами/значениями.

2. **CleanupTransformer**
   - Отфильтровывает записи без обязательных полей и дополняет `defaults`.
   - **Выход:** только валидные записи с заполненными дефолтами.

3. **SideInputProvider** + **SimpleLookupEnricher**
   - Провайдеры подготавливают словари справочников (например, коды стран).
   - `CompositeSideInputProvider` аккуратно мерджит словари по ключу (nested merge для вложенных `dict`).
   - Enricher ищет совпадения по `record_key` и либо добавляет поля, либо вкладывает результат в `merge_to_field`.
   - **Выход:** обогащенные записи, неизмененные при отсутствии совпадения.

4. **SHA256BusinessKeyDeriver**
   - Сериализует выбранные поля (`fields`) в JSON и строит 64-символьный SHA-256 хэш.
   - Строковые значения нормализуются (`strip + lower`) перед хэшированием для устойчивой дедупликации.
   - Хэш помещается в колонку `business_key` (настраиваемо через `field_name`).
   - **Выход:** каждая запись содержит стабильный бизнес-ключ.

5. **BusinessKeyDeduplicator**
   - Удаляет дубликаты по `business_key`, стратегия `keep`: `first` или `last`.
   - **Выход:** последовательность уникальных записей.

6. **HashingTransformer (опционально)**
   - Использует `ColumnHasher` или другой `HasherABC` для вычисления контрольного хэша строки.
   - Результат записывается в поле `row_hash` (по умолчанию) или указанное пользователем.
   - **Выход:** записи с дополнительной колонкой хэша.

## Итоговый output
- Стабилизированные, очищенные и обогащенные записи с полями:
  - бизнес-ключ (64 символа, hex),
  - при необходимости — `row_hash` для отслеживания изменений,
  - дополнительные поля из lookup-справочников.
- Количество записей после пайплайна не больше исходного из-за дедупликации.
