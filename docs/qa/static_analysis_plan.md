# План статических проверок и автоформатирования

## 1. Стек инструментов
- **Ruff** — основной линтер с поддержкой rule set'ов flake8/pyupgrade/bandit/flake8-tidy-imports; достаточно быстрый, чтобы запускать его на каждый коммит.
- **Black** — единый форматер, снимает споры о стиле и гарантирует длину строки 100 символов.
- **isort** — гарантирует стабильный порядок импортов и служит страховкой против ручных конфликтов с автогенерацией Ruff.
- **Mypy** — строгий анализ типов для основного кода (`src/bioetl`, `src/scripts`).
- **Pyright** — продолжает использоваться для IDE/CI (конфигурация уже в `pyproject.toml`).
- **Pre-commit** — запускает форматер и линтеры локально перед пушем, а GitHub Actions (`.github/workflows/ci.yaml`) повторяет те же шаги в CI.

## 2. Конфигурация
Ключевые параметры хранятся в `pyproject.toml`:
- `[tool.ruff]` и `[tool.ruff.lint]` задают таргет `py310`, line length = 100, покрывают группы правил `E/F/B/C4/I/N/SIM/TID/UP/RET/S/A` и включают автофикс (`fixable = ["ALL"]`).
- `per-file-ignores` смягчает безопасность в `tests/**` и CLI-скриптах, чтобы не ломать legacy.
- `[tool.black]` и `[tool.isort]` синхронизированы по line length, используют профиль black.
- `[tool.mypy]` запускается в строгом режиме, но имеет оговорки для проблемных пакетов и тестов.
- `.pre-commit-config.yaml` запускает `isort`, `black`, `ruff`, `flake8`, `mypy` и вспомогательные проверки (секреты, markdown, lychee и т.д.).

## 3. Команды запуска
Упрощённые цели описаны в `Makefile`:
- `make format` — выполняет `ruff check --fix`, затем `isort` и `black` для всего `src/tests/scripts`.
- `make lint` — проверяет `ruff`, `isort --check-only`, `black --check`.
- `make typecheck` — запускает `mypy` c `pyproject.toml`.
- `make qa` — агрегирует `lint` + `typecheck` для локальных pre-flight проверок.

Для CI используется workflow `.github/workflows/ci.yaml`, который устанавливает dev-зависимости и вызывает `pre-commit run --all-files` (включая `ruff`, `black`, `isort`, `flake8`, `mypy`), а затем `mypy` и `pytest --collect-only` в отдельных джобах.

## 4. Автоисправление и ручной разбор
1. **Автоисправление** — всегда начинаем с `make format`. Ruff автоматически поправит мелкие ошибки (`I`, `UP`, `SIM`), isort отсортирует импорты, black приведёт стиль.
2. **Повторное сканирование** — `make lint` подтверждает чистоту. Если остаются ошибки класса `F401` (удаление импортов), `S603/S607` (shell) или сложные предупреждения `B`/`RET`, их стоит проверять вручную.
3. **Типы** — `make typecheck` сообщает об ошибках `mypy`; большинство исправляется добавлением типов или использованием `typing.cast`. Игнорирование допускается только через локальные `# mypy: ignore-errors`/`type: ignore`, чтобы сохранить строгий профиль.

## 5. Поэтапное внедрение
1. **Этап 0** — прогнать `make format` на текущей ветке и закоммитить массовое форматирование (если нужно) отдельно.
2. **Этап 1** — включить обязательный запуск `make qa` перед любыми Pull Request'ами. Для больших фич допускается локальная упаковка `ruff check --select S`/`--select B` для целевых каталогов.
3. **Этап 2** — постепенно ужесточать правила: убрать `per-file-ignores` после рефакторинга тестов/скриптов, уменьшить список `mypy`-override'ов.
4. **Этап 3** — расширить CI: добавить шаг `pytest` (не только `--collect-only`) и отчёт по покрытию после стабилизации.

## 6. Напоминание для разработчиков (prompt)
> Перед каждым коммитом выполняй `make format && make qa`. Если видишь предупреждение Ruff класса `S` или `RET`, оцени влияние на поведение до того, как применять `--fix`. Для спорных случаев добавляй комментарии `# noqa`/`# type: ignore` только с указанием причины.
