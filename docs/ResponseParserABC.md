# ResponseParserABC[ResponseT, ParsedItemT]

## Назначение

`ResponseParserABC` отвечает за преобразование транспортного ответа (`ResponseT`) в поток доменных элементов (`ParsedItemT`) и, при необходимости, за извлечение курсора для пагинации.

Он:
- **не выполняет сетевые запросы**,
- **не знает про ретраи**,
- **не формирует запросы**.

Его зона ответственности — только разбор уже полученного ответа.

## Общее представление интерфейса

```python
from typing import Generic, TypeVar, Iterable, Optional

ResponseT = TypeVar("ResponseT")
ParsedItemT = TypeVar("ParsedItemT")

class ResponseParserABC(Generic[ResponseT, ParsedItemT]):
    def parse_items(self, response: ResponseT) -> Iterable[ParsedItemT]:
        """Разобрать полезные элементы из ответа."""
        raise NotImplementedError

    def extract_cursor(self, response: ResponseT) -> Optional[str]:
        """Извлечь строковое представление курсора для следующего запроса."""
        raise NotImplementedError
```

## Методы

### `parse_items(self, response: ResponseT) -> Iterable[ParsedItemT]`

Назначение: извлечь полезные данные из транспортного ответа.

Примеры источников:
- список JSON‑объектов,
- строки CSV,
- записи из DB‑курcора,
- сообщения очереди.

Требования:
- Возвращаемый `Iterable` должен отражать порядок, заданный источником, если протокол его определяет.
- Не должно быть побочных эффектов, кроме:
  - логирования,
  - инкремента счётчиков/метрик.
- Поведение при одном и том же `ResponseT` должно быть детерминированным.

Работа с частично битым ответом реализуется на уровне конкретного парсера:
- немедленный `raise` при первой некорректной записи;
- пропуск битых записей с репортингом DQ‑ошибок;
- возврат обёрток вида `ValidationResult[ParsedItemT]` (если согласовано со схемой).

### `extract_cursor(self, response: ResponseT) -> Optional[str]`

Назначение: извлечь строковый курсор для следующего запроса.

Поведение:
- Возвращает:
  - строку курсора, если он есть,
  - `None`, если это:
    - первая/последняя страница,
    - или протокол вообще не поддерживает пагинацию.
- Формат курсора (plain‑строка, base64, JSON и т.п.) согласуется с:
  - `RequestBuilderABC`,
  - `PaginatorABC`.

Парсер обязан декодировать курсор так, чтобы его можно было затем без потерь передать в `build_for_page`.

## Ответственность

- Знание протокола и формата ответа:
  - где лежит полезный payload,
  - как закодированы метаданные и курсор,
  - как выглядит «пустой» ответ.
- Интерпретация содержимого:
  - определение валидности полей и структуры,
  - принятие решения: исключение / пропуск / частичный результат.

Транспортные ошибки (таймауты, разрыв соединения, HTTP 5xx и т.п.) **сюда не попадают** и обрабатываются в `SourceClientABC`.

## Инварианты

- При одинаковом `ResponseT`:
  - `parse_items` всегда возвращает одинаковый набор/последовательность элементов;
  - `extract_cursor` всегда выдаёт один и тот же курсор или `None`.
- Порядок элементов в `Iterable[ParsedItemT]` должен совпадать с порядком в оригинальном ответе, если он определён протоколом.
- Парсер не делает повторных сетевых запросов и не инициирует ретраи.

## Взаимодействие с другими компонентами

- **`SourceClientABC`**:
  - поставляет готовый `ResponseT` (HTTP‑ответ, DB‑курсор и т.п.);
  - транспортные ошибки обрабатываются до вызова парсера.

- **`PaginatorABC`**:
  - вызывает `extract_cursor` для получения курсора следующей страницы;
  - формат курсора должен быть стабильным и задокументированным.

- **`TransformerABC`**:
  - получает уже разобранные `ParsedItemT`;
  - не знает о протоколе, курсорах и структуре транспортного уровня.

## Типизация

- `ResponseT` и `ParsedItemT` инвариантны.
- Если парсер объявлен как `ResponseParserABC[HttpResponse, Dict[str, Any]]`, реализация не должна:
  - возвращать наследников вместо `Dict[str, Any]`,
  - менять типы в подписи методов.

## Ошибки

- Транспортные ошибки:
  - сюда не попадают,
  - обрабатываются в клиентском коде/ретраях.

- Протокольные/форматные ошибки:
  - отсутствие обязательного поля,
  - неверный тип поля,
  - некорректный JSON/CSV/структура.
  - В этих случаях парсер может:
    - выбросить исключение (обработка через `ErrorPolicyABC`),
    - либо применить заранее определённую стратегию деградации.

## Ошибки использования

- Смешивание в парсере:
  - логики ретраев,
  - сетевых вызовов,
  - бизнес‑валидации, не связанной с форматом ответа,
  затрудняет отладку и нарушает разделение ответственности.
