# RateLimiterABC

## Назначение

`RateLimiterABC` описывает минимальный контракт для локального ограничения:

- частоты запросов (RPS),
- количества одновременных операций (concurrency).

Используется, чтобы не перегружать внешний API или ресурс, независимо от конкретной реализации лимитера.

## Синхронный интерфейс

```python
class RateLimiterABC:
    def acquire(self) -> None:
        """Заблокировать выполнение до получения слота для операции."""
        raise NotImplementedError

    def release(self) -> None:
        """Освободить ранее занятый слот."""
        raise NotImplementedError
```

### `acquire(self) -> None`

Назначение: дождаться разрешения на выполнение операции.

Варианты поведения:

- блокировать до тех пор, пока лимит не позволит продолжить;
- выбросить предсказуемое исключение при невозможности продолжения (например, режим жёсткого shutdown).

Требования:

- метод не должен «сам по себе» вызывать `release`;
- детали блокировки (mutex, условная переменная, внутренняя очередь) — вне контракта.

### `release(self) -> None`

Назначение: сигнализировать об окончании операции и освободить слот.

Требования:

- на каждый успешный `acquire` должен приходиться ровно один `release` со стороны вызывающего кода;
- реализация должна быть устойчива к ошибкам вызывающего кода:
  - либо явно падать при двойном `release`,
  - либо безопасно игнорировать.

### Инварианты

- `acquire` либо блокирует, либо бросает явно документированное исключение;
- `release` при корректном использовании не ломает внутреннее состояние лимитера;
- интерфейс не навязывает модель потоков:
  - однопоточный код,
  - многопоточный код с mutex’ами,
  - и т.п.

## Асинхронный интерфейс: AsyncRateLimiterABC

Для асинхронного кода используется отдельный контракт `AsyncRateLimiterABC` с таким же смыслом, но на `async`-методах:

```python
class AsyncRateLimiterABC:
    async def acquire(self) -> None:
        """Дождаться слота для операции в асинхронном контуре."""
        raise NotImplementedError

    async def release(self) -> None:
        """Освободить ранее занятый слот."""
        raise NotImplementedError
```

Требования и инварианты аналогичны синхронному варианту:

- один `release` на каждый успешный `acquire`;
- отсутствие скрытого I/O внутри методов, кроме собственно синхронизации;
- детерминированное поведение при корректном использовании.

`AsyncRateLimiterABC` применяется в асинхронных реализациях `SourceClientABC` и других клиентов, работающих поверх `async`-транспортов.

## Типичные модели ограничения

1. **Семафор по числу параллельных запросов**
   - Внутренний счётчик свободных слотов:
     - `acquire` уменьшает счётчик (или блокирует при нуле),
     - `release` увеличивает.
   - Контролирует уровень конкаррентности.

2. **Token bucket для RPS**
   - `acquire` блокирует до появления токена.
   - Фоновая логика пополняет токены с заданной скоростью.
   - Можно ограничивать как средний RPS, так и burst-размер.

3. **Комбинированные схемы**
   - Одновременное ограничение по RPS и по числу параллельных запросов.
   - Детали реализации остаются внутри конкретного лимитера.

## Взаимодействие с другими компонентами

- **`SourceClientABC` (синхронный)**:

  ```python
  limiter.acquire()
  try:
      return self._send_internal(request)
  finally:
      limiter.release()
  ```

- **Асинхронный клиент источника**:

  ```python
  await limiter.acquire()
  try:
      return await self._send_internal(request)
  finally:
      await limiter.release()
  ```

- На уровне пайплайна лимитер обычно прокидывается как зависимость клиента; остальные стадии его напрямую не используют.

## Ошибки и сбои

- При исключениях в операции `release` должен вызываться в `finally`.
- Лимитер может вести внутреннюю статистику, но это не часть контракта; за метрики отвечают отдельные компоненты (`TracerABC`, `ProgressReporterABC` и т.п.).

## Ошибки использования

- Забытый `release` приводит к «утечке» слотов и блокировке дальнейших запросов.
- Смешивание в лимитер:
  - логики ретраев,
  - подсчёта метрик,
  - бизнес-ограничений
  раздувает интерфейс и мешает повторному использованию.
