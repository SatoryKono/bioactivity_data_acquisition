# Карта дублирования базовых классов

## Сводка дубликатов
- В клиентских классах `Chembl*Client` повторяется шаблон наследования от `_BaseEntityClient` с единственным отличием — значением `entity` в конструкторе.
- Во всех парсерах (`activity`, `assay`, `target`, `testitem`, `document`) повторяется идентичная функция `_extract_items` и общий паттерн построения `DataFrame` из полей словаря.
- В нормализаторах (`normalize_activity`, `normalize_assay`, `normalize_target`, `normalize_testitem`, `normalize_document`) дублируется подготовка копии `DataFrame`, заполнение строковыми столбцами, вычисление `business_key`, `business_key_hash` и `row_hash`, затем валидация через схему.

## Таблица групп дублирования
| Группа | Файлы/модули | Тип дубликата | Комментарий |
| --- | --- | --- | --- |
| Клиенты сущностей | `src/bioetl/clients/entities/client_activity.py`, `client_assay.py`, `client_target.py`, `client_testitem.py`, `client_document.py` | Полный дубликат шаблона конструктора | Отличается только строковый идентификатор сущности; вся логика наследуется от `_BaseEntityClient`. |
| Парсеры ChEMBL | `sources/chembl/*/parser/*_parser.py` | Полный дубликат `_extract_items`; частичный дубликат сборки записей | Структура функции одинаковая, меняются лишь отображения полей в результирующий словарь. |
| Нормализаторы ChEMBL | `sources/chembl/*/normalizer/*_normalizer.py` | Множественные вариации одного паттерна | Повторяются шаги копирования, приведения типов к string, заполнения пропусков, вычисления бизнес- и строковых хэшей, валидации схемой; варьируются наборы столбцов и используемая схема. |

## Общие абстракции
1. **Базовый/фабричный клиент сущностей**: функция-фабрика `make_chembl_client(entity: str)` или реестр `ChemblEntityClient(entity: str)` с набором допустимых идентификаторов. Устраняет необходимость в пяти однотипных классах-конструкторах, сохраняя API получения клиента.
2. **Утилита парсинга коллекций**: вынести `_extract_items` и общую сборку `DataFrame` в модуль `bioetl.sources.chembl.parsers.common`, предоставив функцию `extract_items(payload)` и хелпер для маппинга полей (`build_records(payload, mapping)`). Это позволит параметризовать отображение полей без копирования логики обхода пагинационных ответов.
3. **Базовый нормализатор/миксин**: реализовать класс `ChemblNormalizerBase` с методами `prepare_strings(df, columns_with_defaults)` и `add_hashes(df, business_key_column, all_columns)`, либо функциональные хелперы в `bioetl.sources.chembl.normalizers.common`. Конкретные нормализаторы будут задавать только список столбцов и схему, делегируя общие шаги базовому коду.

## План рефакторинга
1. Добавить модуль общих утилит парсера с `extract_items` и генерацией записей по конфигурации столбцов; заменить приватные `_extract_items` во всех парсерах на вызов утилит.
2. Создать базовый класс/миксин для нормализаторов, инкапсулирующий преобразование типов, заполнение по умолчанию и вычисление `business_key_hash`/`row_hash`; нормализаторы будут передавать только специфику столбцов и схемы.
3. Ввести фабричный метод для клиентов ChEMBL (например, `ChemblEntityClientFactory`) или общий класс с параметром `entity`, чтобы не дублировать тривиальные подклассы, сохранив публичное API через алиасы.
4. Провести миграцию существующих модулей на новые абстракции без изменения внешних точек входа (сигнатуры функций `parse_*` и `normalize_*`, используемые CLI/тестами).
5. Обновить документацию и добавить типы/валидацию для новых утилит, чтобы подчеркнуть ожидаемые поля и типы.

## Итоги реализации
- Введён модуль `bioetl.sources.chembl.common` с утилитами парсинга (`ColumnMapping`, `build_records_from_payload`, `extract_items`) и общим нормализатором (`BaseChemblNormalizer`, `ColumnNormalizationSpec`) с строгими типами.
- Все парсеры ChEMBL используют общие маппинги столбцов и извлечение элементов вместо приватных `_extract_items`.
- Нормализаторы ChEMBL переводены на общий базовый класс с единообразным вычислением `business_key_hash` и `row_hash`.
- Добавлена фабрика `ChemblEntityClientFactory` и единый класс `ChemblEntityClient`; публичное API сохранено через алиасы `Chembl*Client`.

## Тесты для покрытия консолидации
- Юнит-тесты для общего парсера: проверка, что `extract_items` корректно обрабатывает словари, списки и отсутствующие поля; проверка маппинга полей для каждого сущностного парсера.
- Юнит-тесты для базового нормализатора: приведение типов, заполнение значениями по умолчанию, корректное вычисление `business_key_hash` и `row_hash` при разных наборах столбцов.
- Интеграционные тесты клиентов: фабрика/унифицированный клиент создаёт корректные маршруты для запросов (`/{entity}/{id}`) и использует пагинацию из `_BaseEntityClient`.
- Регрессионные тесты схем: существующие `ActivitySchema`, `AssaySchema`, `TargetSchema`, `TestItemSchema`, `DocumentSchema` валидируют выход нормализаторов после рефакторинга.
