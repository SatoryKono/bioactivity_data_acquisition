# План ответа: refactor-analysis-report

1. Сформировать глобальную таблицу функций на основе собранного AST-анализа и подготовить артефакты `functions_map.csv` / `functions_map.json`.
2. Проанализировать кластеры идентичных и похожих функций, описать причины совпадений и потенциальные точки унификации.
3. Сформировать рефакторинговый бэклог (8–15 задач) с приоритетами, усилиями, DoD и ожидаемым эффектом, учитывая выявленные дубли и архитектурные закономерности.

План аудита кода и рефакторинга
Цель
Создать инструмент для автоматического анализа кодовой базы, выявления дубликатов функций, построения графа вызовов и генерации плана рефакторинга.

Этапы реализации

1. Создание модуля AST-анализа (src/bioetl/tools/code_audit.py)

Функционал:

- Парсинг всех .py файлов в `pipelines/`, `clients/`, `schemas/`, `config/` и подпапках.
- Извлечение функций/методов через AST:
  - Имя функции.
  - Параметры (имя, тип, значения по умолчанию, `*args`/`**kwargs`).
  - Аннотации возвращаемого типа.
  - Докстринг (первая строка).
  - Путь к модулю.
- Нормализация AST-деревьев для сравнения (удаление комментариев, пробелов, нормализация порядка).

Структура данных:

```python
@dataclass
class FunctionInfo:
    full_name: str  # package.module:function
    module_path: Path
    signature: dict[str, Any]  # параметры, аннотации
    returns: str | None
    doc: str | None
    ast_hash: str  # хэш нормализованного AST
    kind: str  # utility/io-client/schema-validator/transform/orchestration/config-loader
```

1. Построение графа вызовов (src/bioetl/tools/call_graph.py)

Функционал:

- Обход AST для поиска `ast.Call` узлов.
- Сопоставление вызовов с функциями по именам и импортам.
- Построение графа: функция → список вызываемых функций.
- Определение принадлежности к пайплайнам (по пути модуля).

Зависимости:

- Стандартный `ast` (обязательно).
- Опционально: `pyan3` для более точного анализа (если доступен).

1. Группировка функций по сходству (src/bioetl/tools/function_clustering.py)

Алгоритм:

- Идентичные функции: одинаковое имя + эквивалентные сигнатуры + одинаковый AST-хэш.
- Близкие функции: высокая похожесть по сигнатурам, типам возврата, множеству вызовов.

Метрики:

- Сравнение AST-деревьев (структурное сходство).
- Сравнение сигнатур (имена параметров, типы).
- Сравнение графа вызовов (общие вызываемые функции).

1. Генерация отчётов (src/bioetl/tools/refactoring_report.py)

Формат вывода:

- Markdown-таблица (`artifacts/functions_map.md`) с колонками `Function | Signature | Returns | Kind | Pipelines used in | Module path | Doc`.
- CSV-файл (`artifacts/functions_map.csv`) для машинной обработки.
- JSON-файл (`artifacts/functions_map.json`) с полной структурой данных.
- Группировки (`artifacts/duplicate_groups.md`):
  - Duplicate groups (identical).
  - Similar groups (near-duplicate).
- План рефакторинга (`artifacts/refactoring_plan.md`) с промтами для изменений.

1. CLI-интеграция (src/bioetl/cli/tools/code_audit.py)

Команда: `bioetl-code-audit`.

Параметры:

- `--artifacts-dir`: каталог для сохранения отчётов (по умолчанию `artifacts`).
- `--target-dirs`: список каталогов для анализа (по умолчанию `pipelines,clients,schemas,config`).
- `--format`: формат вывода (`markdown`, `csv`, `json`, `all`).
- `--min-pipelines`: минимальное количество пайплайнов для унификации (по умолчанию 3).

1. План рефакторинга

Шаблоны промтов:

- P0/M Вынести дублирующуюся функцию — унификация идентичных функций.
- P0/S Создать абстракцию для близких функций — Protocol + адаптеры.
- P1/S Нормализовать сигнатуры и типы — выравнивание сигнатур.
- P1/M Централизовать клиентов — общий слой клиентов.
- P1/S Общие схемы/валидаторы — консолидация валидаторов.
- P1/S Общая утилита конфигов — единая точка загрузки.
- P2/M Конвенции по именованию — переименование и реэкспорты.
- P2/M Тест-матрица — параметризованные тесты.

Структура файлов

```text
src/bioetl/tools/
├── code_audit.py          # Основной модуль анализа
├── call_graph.py          # Построение графа вызовов
├── function_clustering.py # Группировка функций
└── refactoring_report.py  # Генерация отчётов

src/bioetl/cli/tools/
└── code_audit.py          # CLI-команда

artifacts/
├── functions_map.md       # Markdown таблица
├── functions_map.csv      # CSV для машинной обработки
├── functions_map.json     # JSON с полной структурой
├── duplicate_groups.md    # Группировки дубликатов
└── refactoring_plan.md    # План рефакторинга
```

Критерии качества

- Покрытие: ≥95% `.py` модулей в указанных каталогах.
- Корректность сигнатур: совпадение с аннотациями ≥90%.
- Вызовы: попадание в граф для всех основных пайплайнов.
- Детерминизм: одинаковый вход → одинаковый выход (стабильная сортировка).

Зависимости

Обязательные:

- `ast` (стандартная библиотека).
- `pathlib`, `dataclasses`, `typing` (стандартная библиотека).

Опциональные (для расширенного анализа):

- `pyan3` — для более точного графа вызовов.
- `jedi` — для точных сигнатур при динамических импортов.

Риски и ограничения

- Статический анализ не учитывает динамические вызовы через `getattr()`, `eval()`.
- Сложные динамические импорты могут быть не распознаны.
- При отсутствии аннотаций типы выводятся приблизительно.
- Анализ больших файлов может быть медленным.

Тестирование

- Юнит-тесты для AST-парсинга.
- Тесты группировки функций на известных примерах.
- Интеграционные тесты на реальных модулях проекта.
- Golden-тесты для отчётов (детерминизм вывода).
